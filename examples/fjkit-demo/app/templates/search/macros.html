Why each of them: - `hx-trigger=" from:body"` — the server fires the event through `HX-Trigger`, and htmx raises it on the element that made the request. The panels are nowhere near that element, so they listen where it bubbles to. Each event needs its own `from:body`; a bare second name would be read as an event on this element. - `hx-vals="js:…"` — the id rides in `event.detail`, and this is the single place it turns back into a query parameter. Doing it here, rather than remembering the selection on the server, is what keeps the endpoints stateless and two open tabs independent. - `hx-include` — the region also depends on the search box, and that value is on the page rather than in the event. A selector, so no fragment has to be handed the query it is already displayed next to. - `hx-target="this"` with `hx-swap="outerHTML"` — every subscriber replaces itself, so the reply is one region and the sender never has to know how many regions exist. `events` is the list this fragment has a reason to hear.
