{# The chart component. One macro, called three times — which is CLAUDE.md's rule about repeated components, and it matters more here than usual: an `{% include %}` in a loop would re-parse the same figure scaffolding per chart on every swap. What the markup deliberately does *not* contain: * a colour. The figure carries none; the series run on Plotly's palette and the chart's chrome — axis text, grid lines, the gaps between pie slices — is resolved from the live tokens by `static/js/charts.js`. A hex code here would fail `fjkit check`, and be wrong in one of the themes. * a class. There is no chart class in fjkit's vocabulary, and inventing one in an app template is how a closed vocabulary stops being closed. The card around it is the component; the figure is a plain box. * a height. It rides in `data-height` and is applied by the same script that draws, because a `style=""` attribute in markup is the other way an app starts writing CSS. `
