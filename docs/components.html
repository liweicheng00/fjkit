Every macro, and the call that made it

Every macro, with a live preview and the call that produced it. Turn the knobs and two things change together: the component, and the Jinja you would have typed to get it. Every preview was rendered by fjkit's own Environment at build time.

01

Every macro: the call and the HTML

No macro accepts a class string, so no call site can invent a colour.

Every parameter below is a closed enumeration. There is no class= escape hatch and no hue to pass. You pick a variant, and the token layer decides what that looks like. Anything extra you hand a macro becomes an HTML attribute: hx_post="/tasks" renders as hx-post="/tasks". That is how htmx stays out of every macro definition.

Layout: stack, row, grid, split
The moment you type grid gap-4, the no-build promise is over.
      

      
      

        Components alone do not get you to a closed vocabulary. The first time you need two cards
        side by side you reach for a utility class, and the stylesheet fjkit shipped has no idea you
        wanted it. So spacing and columns are macros too. Every value is a lookup whose entries
        appear verbatim in the kit's source, where Tailwind can see them.
      

      

        The dashed tiles are your content. Change the knobs and watch the source line change with them.

page_header, section, divider
A heading, a rule and a group are components too — or they are utility classes.
      

      
      

        These three are what a page is made of before any of its data arrives.
        page_header takes a block, and the block is its actions. A title, a description
        and a row of buttons stay on one line at every width, with no caller measuring anything. The
        header at the top of this page is the same macro, called plainly, with no actions to place.
      



    
    

      


page_header(title, description) · block = actions

empty_state, metric_group, lists
Everything else in data.html — the pieces that display a value.
      

      
      

        A table full of rows is the easy case. These are the others: the count that has no rows
        behind it yet, the row of numbers above a table, the sentence with a key combination in it.
      

      

        empty_state is worth knowing before you need it. table renders it
        for you when rows is empty, so no caller writes the if-rows-else branch.

      05


      


icon(): any Lucide name, inlined
1,767 names, no sprite sheet, no icon font, no request.
      

      
      

        icon("plus") inlines the Lucide path as an <svg>. It
        inherits currentColor, so an icon inside a primary button is already the right
        colour, and it costs no network request at any size.
      

      

        Most macros take icon_name= directly: button, stat,
        empty_state, brand, sidebar_link. So you rarely call
        this one yourself. The links in this site's sidebar are all of them. A sample of the set is
        below, and any Lucide name works.
      




    

      


icon(name, size=16)
      

    
      
        




  


            

      

        An unknown name raises at render time rather than printing an empty box, so a typo fails the
        page that has it instead of shipping a hole in the interface.

When a macro is missing
      

    
      
    

      
check the parameters
most requests are a keyword that already exists — size, tone, padded, align
    
  
    

      
pass it through
any extra keyword becomes an attribute, which covers every hx-*, aria-* and data-*
    
  
    

      
fjkit eject
copy the component into your app to edit it — and lose upstream fixes to it
    
  
    

      
open an issue
a blocked class names the component that does not exist yet; that is the report
