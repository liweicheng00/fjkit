fjkit 是怎麼組起來的

五張圖，對應五個已經定案的架構決定。決定了什麼、為什麼，在 CHARTER.md 第 3 節； 這一頁畫的是那些決定長什麼樣子。

01 A2

套件邊界

你的 app 只在四個地方碰到 kit，其餘都封在套件裡。

四條箭頭都是單向的。你的 app 依賴 fjkit；kit 不會反過來引用你的 app， 也不知道你的資料長什麼形狀。

brand.css 就是全部的設定介面，內容是純 CSS 變數。沒有任何步驟會編譯它。

這讓你的專案少掉什麼

一份 Tailwind 安裝

那支執行檔在 fjkit 發佈時跑，不在你的 app 跑

一個 watcher

改完模板沒有任何東西要重新 build

一支 vendoring 腳本

htmx 與 Basecoat 版本釘在 wheel 裡，由 mount_fjkit 供應

02 A5

模板解析，以及 eject 改變了什麼

app 的模板目錄排在前面，所以同一行 import 在 eject 前後解析到不同檔案——而呼叫端一個字都不用改。

{% from "ui/button.html" import button %}

eject 之前

① app/templates/ui/button.html

不存在——loader 往下找

② fjkit/templates/ui/button.html

命中，渲染的是這一份

fjkit eject button 之後

① app/templates/ui/button.html

命中，渲染的是這一份

② fjkit/templates/ui/button.html

不會走到

遮蔽是功能，不是意外：ChoiceLoader 把你的目錄排在套件前面。

代價是 eject 出去的檔案不再收到上游修正，所以文件不主推它。 fjkit eject 只複製你指名的 macro，其餘重新匯出，所以你接手的檔案很小 ——以 badge 為例，49 行對上原本的 289 行。

03 A1

build 發生的時機

兩邊跑的是同一條管線。差別在誰來跑，以及跑幾次。

每個 app 自己 build

你的模板 + 元件 CSS

一起進 Tailwind CLI

那支 CLI

你要裝、你要釘版本、你要跑

--watch

工作期間得一直開著

產出

是你的部署流程必須生出來的一個檔案

fjkit 在發佈時 build

kit 的模板 + 元件 CSS

進同一支 CLI，在 fjkit 的 CI，只跑一次

產出

隨 wheel 出貨，每個風格包一份

你的 brand.css

是第二個 <link>，不是第二次 build

--watch

在你這端不存在

以本站載入的那個風格包實測：236 KB 原始、25.2 KB gzip， 預算是 build 會強制執行的 28 KB。原始大小裡約 217 KB 是 Basecoat 自己的元件層，無論 fjkit 在它上面寫了一個 macro 還是四十個，都整份出貨。

04 A6

渲染路徑：一份 partial，兩個入口

完整頁面與 htmx swap 走不同的路，落在同一份模板上。

_board.html 有兩條進、兩條出，中間只有一份定義。第一次繪製看到的東西， 與 swap 換上去的東西，因此渲染自同一份原始碼，不可能漂移。 

@router.get("/tasks", name="tasks_page")
@render("tasks/page.html", partial="tasks/_board.html")
def tasks_page(service: TaskServiceDep) -> BoardResponse:
    return board(service)

保證來自 partial=。同一條路由對導覽回整頁、對 htmx 請求回片段， 所以不存在第二條路由要跟著維護。

05 A7

守門迴圈

封閉詞彙表要成立，違反就必須失敗。而每一次失敗，都指出少了哪個元件。

這個迴圈

① 你寫模板

然後伸手去拿 kit 不會吐出來的 class——例如 grid-cols-7

② fjkit check 讓 build 失敗

那個 class 不在白名單裡，而白名單是從 Basecoat 自己的 CSS 推導出來的，不是手工維護的

③ 被擋下的 class 就是答案

它指出一個還不存在的元件，或一個還不存在的 macro 參數

④ 把它補進 ui/*.html

下一份需要它的模板就會通過

這條回饋邊是 kit 唯一的擴張機制，而示範 app 是它的測試案例。0.1 完成時實測： 同樣的畫面在 fjkit 之前寫出來有 258 個違規；用 kit 重寫之後是 0。

這個檢查也擋「目前碰巧存在的 utility」。app 若因為 shell 剛好吐出 gap-4 就拿來用，哪天 shell 不吐了，它就會無聲壞掉。
