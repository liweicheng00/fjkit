FastAPI 沒有附的那層 UI

頁面、表格、表單、導覽、深色模式與 htmx 局部更新——都是你從 handler 所在的同一份程式碼裡 呼叫的 Jinja macro，而且你這端不需要任何前端工具鏈。

第一次來？這個站既是文件，也是證據。

三頁全部是同一支 fjkit app。

你在這裡看到的每一個元件，都是由 fjkit 自己的 Jinja Environment 渲染出來的；而它周圍那些東西 ——這張 card、側欄、表格——是同一批 macro 蓋的。fjkit check 在 CI 裡掃這些模板， 所以這個站不可能給你看套件裡沒有的元件，也不可能寫出一個 app 不被允許寫的 class。

01

fjkit 是什麼

一個畫面就是一條路由、一份模板，加上幾個 macro 呼叫。

fjkit 是你的 FastAPI handler 與瀏覽器之間的那一層。接線只做一次，之後每個畫面都是一份 呼叫 macro 的模板：page_header、card、table、 form、sidebar。沒有第二個應用程式要建置，沒有第二種語言， 出事的時候也沒有第二個地方要找。

撐住其餘一切的那個限制：Tailwind 跑在 fjkit 發佈的時候，不是跑在你的 app 執行的時候。 你的 repo 裡沒有 package.json、沒有 node_modules、沒有 Tailwind 執行檔， 改完模板也沒有任何東西要重建。底下兩個檔案都是直接從這個 repo 裡的 demo app 讀出來的。 

"""The demo app, built on fjkit.

Compare with the pre-fjkit version (`git show 2ef74c9:app/main.py`): the
Environment, the vendored assets and the whole stylesheet pipeline are gone.
What is left is two lines of wiring — a config and a mount — and the
app's own routes.
"""

from __future__ import annotations

from contextlib import asynccontextmanager
from pathlib import Path
from time import perf_counter

from fastapi import FastAPI
from fjkit import FjkitConfig, mount_fjkit
from fjkit.vendored import STYLE_PACKS

from app.features.dashboard.router import router as dashboard_router
from app.features.jobs.router import router as jobs_router
from app.features.jobs.service import JobService
from app.features.tasks.router import router as tasks_router
from app.features.tasks.service import TaskService

APP_DIR = Path(__file__).resolve().parent
ROOT_DIR = APP_DIR.parent

#: Where the kit's assets are served from. Spelled out rather than left to the
#: default because the picker below builds URLs under the same prefix, and two
#: places guessing it separately is how a mount and a link drift apart.
STATIC_URL = "/_fjkit"

#: Every style pack, and the URL its stylesheet is served from.
#:
#: fjkit resolves exactly one pack per process (`FjkitConfig.style`), and that
#: stays true here — the shell links `fjkit-vega.css` like it always did. What
#: this feeds is the demo's picker: all eight packs ship in the wheel and
#: `mount_fjkit` serves the whole static directory, so the browser can be pointed
#: at another one to compare them without a restart. That is an affordance of
#: this demo, not something the kit does, which is why the map is built here.
#:
#: A dict rather than a list because the picker's script looks a pack up in it:
#: a value that is not one of the eight has no URL, so a stale or hand-edited
#: `localStorage` entry cannot turn into a 404 and an unstyled page.
STYLE_SHEETS = {pack: f"{STATIC_URL}/dist/fjkit-{pack}.css" for pack in STYLE_PACKS}

#: The app's templates are searched before fjkit's, so dropping a file at
#: `templates/ui/button.html` would shadow the kit's — that is `fjkit eject`.
config = FjkitConfig(
    template_dir=APP_DIR / "templates",
    bytecode_cache_dir=ROOT_DIR / ".jinja-cache",
    static_url=STATIC_URL,
    globals={"style_sheets": STYLE_SHEETS},
)


@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.tasks = TaskService()
    # Background jobs live here for the same reason tasks do: one store per
    # process, so a job started by one request is visible to the poll that
    # follows it. A real app swaps this for a queue; the routes do not change.
    app.state.jobs = JobService()
    yield


def create_app() -> FastAPI:
    app = FastAPI(title="fjkit demo — task board", lifespan=lifespan)

    @app.middleware("http")
    async def server_timing(request, call_next):
        """Publish wall time as `Server-Timing`, so the browser's network panel
        shows the server cost of every page and every htmx swap."""
        started = perf_counter()
        response = await call_next(request)
        response.headers["Server-Timing"] = f"app;dur={(perf_counter() - started) * 1000:.2f}"
        return response

    # Serves fjkit's stylesheet and the vendored htmx/Basecoat JS straight out
    # of the installed package, and builds the Jinja Environment once. The app
    # has no static assets of its own.
    mount_fjkit(app, config)

    app.include_router(dashboard_router)
    app.include_router(tasks_router)
    app.include_router(jobs_router)

    @app.get("/health", include_in_schema=False)
    async def health() -> dict[str, str]:
        return {"status": "ok"}

    return app


app = create_app()
兩個呼叫：FjkitConfig 收下所有旋鈕；mount_fjkit 直接從安裝好的套件裡供應 stylesheet 與 vendored JS，並且每個 process 只建一次 environment。
{#

  same partial the htmx endpoints return. Nothing about a task row is written
  twice, so a change to the board cannot land in one place and miss the other.
#}
{% extends "base.html" %}

{% from "ui/data.html" import kbd %}

注意一頁裡沒有什麼：沒有 utility class、沒有顏色、沒有 <svg>，也沒有藏在元件裡的 htmx 樣板碼。

那些「沒有」不是風格偏好。一份在發佈時就編譯好的 stylesheet，裡面只可能有發佈當下存在的 class ——所以詞彙表必須是封閉的，而且模板一踏出去， 就有一個指令會讓 build 掛掉。

02

給誰用

會寫後端、需要一個像樣的介面、又不想碰前端工具鏈的人。

如果你已經會寫 FastAPI，而你需要導覽、深色模式、一張可篩選的表格，以及一個會驗證的表單 ——這是給你的。如果你要帶 React、Vue 或 Svelte 進來，那這一層就選錯了，而這是一個決定， 不是一個缺口。

它應該花你多少

第一頁

大約二十行 Python 就有導覽與深色模式，而且沒有建置步驟

一個後台畫面

列表、篩選、新增表單與 htmx 更新，一個下午，不必寫 CSS 或 JavaScript

換品牌

一份覆寫 token 的 stylesheet，掛在 kit 的後面

升級

改一個版本號——stylesheet 在 wheel 裡，不在你的 repo 裡

它刻意不是什麼

資料層

沒有 ORM、沒有後台產生器、沒有登入。fjkit 負責渲染；要渲染什麼由你的 app 決定

前端 API

JSON 是一等公民，但它描述的是「這一頁拿到的資料」——不是為了另一個前端渲染器而維護的第二份契約

每個方向都能設定

參數是封閉列舉，因為一份參數表必須有能力說不

偽裝過的 Node 工具鏈

fjkit 自己的 CI 可以用；你的 app 永遠不用

03

六個決定，以及撐住它們的東西

每一條都是一個承諾，而每個承諾都有一樣東西撐著它。

這些已經定了，文件其餘部分都建立在它們之上。一個沒有東西在執行的承諾，只是 README 裡的一句話 ——第三欄就是把每一條變成「build 掛得掉」的那樣東西。

決定 它換到什麼 什麼撐住它
你這端零建置 沒有工具鏈、沒有 watcher，改完模板沒有任何東西要重建 wheel 裡就帶著編譯好的 stylesheet、htmx 與 Basecoat
class 詞彙表是封閉的 出貨的那份 stylesheet 永遠夠用，因為連版面都是元件 fjkit check，跑在你的 CI，也跑在我們的
一個顏色旋鈕 換品牌是改一個檔案，而且改完「綠色仍然代表完成」 每個顏色都是 token；模板指名角色，永遠不指名色相
簽名就是契約 macro 不可能吐出一個不存在的 class 封閉列舉；多的關鍵字變成 HTML 屬性，僅此而已
一份 partial，兩個入口 整頁與 htmx 局部更新不可能長歪成兩個樣子 頁面 include 的，就是端點回傳的那一份 partial
一個標註，兩種傳輸格式 每一個 htmx 端點本來就已經是 JSON API——不必第二條路由、不必 serializer、不必維護一份會走鐘的 DTO 沒有瀏覽器在等標記時，@render 就把 model 序列化出去

每一條背後的理由寫在 repo 的 CHARTER.md 第 2 節，而 「上手」那一頁會在瀏覽器裡示範其中四條 ——包括那個品牌旋鈕，你會看著整頁在眼前重新上色。

最後一條是大家不會預期的那條，值得直接講白。fjkit 的 handler 回傳的是 model，不是標記； @render 依「呼叫端有沒有在等標記」決定傳輸格式。所以 GET /tasks/board 對 htmx 回一塊渲染好的看板，對 curl 回 BoardResponse 的 JSON——同一條路由、同一個 handler、同一個回傳標註， 而 FastAPI 早就把它寫進 /docs 了。 那份回應的兩半都在「上手」頁上。

04

wheel 裡裝了什麼

一個 wheel、兩個執行期依賴，沒有任何東西要你自己編譯。

套件裡帶的

templates/ui/

那些 macro——版面、按鈕、資料、表單、表格、分頁、導覽、側欄、回饋、圖示，以及文件外殼

static/dist/fjkit-<pack>.css

編譯好的 stylesheet，每個風格包一份：234 KB 原始、23.9 KB gzip，在 build 自己守著的 28 KB 預算內。一頁只載一份

static/vendor/

htmx 與 Basecoat 的 JavaScript，版本釘死，直接從套件裡供應

1,767 個圖示

Lucide，按名字內嵌——沒有 icon font、沒有 sprite 請求、執行期沒有 JS

你會碰到的全部表面

FjkitConfig、mount_fjkit

接線，每支 app 一次

@render

在裝飾器上指名模板；handler 只回資料

fjkit check

詞彙表關卡——放進你的 CI

fjkit eject

逃生口：把元件複製進你的 app 再改

需求：Python 3.13 以上，以及兩個執行期依賴——FastAPI 與 Jinja2。要加第三個，需要一個到目前 為止還沒有人提得出來的理由。

接下來去哪

讀一頁，或把 demo 跑起來。兩件事都大約十分鐘。

這個站上

上手

kit 怎麼接、htmx 送出什麼，以及那個會讓 build 掛掉的關卡

元件

每個 macro，實際渲染，附上產生它的那行呼叫

在 repo 裡

examples/board/

一支能跑的 app——router、service、schemas，以及三種模板

src/fjkit/templates/ui/

每個 macro，以及這個站台據以生成的簽名註解

src/fjkit/static/src/fjkit.css

token 表、深色模式，以及品牌旋鈕碰不到的東西

docs/jinja-performance.md

benchmark 真正量到什麼，以及真正慢的那三件事

CHARTER.md

路線圖，以及這個專案要求自己遵守的規則

或者直接跑 demo

uv sync
uv run fastapi dev examples/board/app/main.py
一個總覽頁、一塊有 htmx 局部更新的任務板，以及一份串流出去的兩萬列報表——原始碼就在 examples/board，它同時也是這個 kit 的驗收測試。沒有 CSS 要 build， 也沒有 watcher 要開著。uv run fjkit check app/templates 是你的專案唯一多出來的指令。
