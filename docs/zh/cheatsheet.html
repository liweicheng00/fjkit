fjkit 速查表

kit 出貨的每一支 macro，依用途分組，並在每一列標出這支 macro 要不要用區塊呼叫、區塊裡放什麼。 元件那一頁看它們跑起來，這一頁用來查。

怎麼讀這張表

一列上有什麼，以及兩條每一列都適用的規則。

Jinja macro 有兩種呼叫方式，從名字看不出來是哪一種。裡面不放東西的 macro 直接印出來。會包住東西的 macro 用 {% call %} 呼叫，{% call %} 與 {% endcall %} 之間的內容交給 macro 擺放，Jinja 稱之為 caller 區塊。底下每一支需要區塊的 macro 都掛了一個標籤。 

{% from "ui/data.html" import badge, card %}

{# 直接印出——這支 macro 不吃區塊 #}
{{ badge("Doing", variant="info") }}

{# 區塊——card 會把它當成內容渲染 #}
{% call card("Tasks", "目前所有進行中的事項。") %}
  <p>任何該放進卡片裡的東西。</p>
{% endcall %}

一列上有什麼

簽名

那一行呼叫，含每個參數與預設值。清單上方的標題就是要 import 的檔案

區塊標籤

在列的右邊，只出現在有區塊的列：這支 macro 要用 {% call %} 呼叫，標籤寫的是區塊裡放什麼。沒有標籤就用 {{ }} 印出來

底下那一行說明

簽名沒說的事；簽名說完的就不寫

兩條通則

多出來的關鍵字

簽名裡沒有的關鍵字一律變成屬性，底線換成連字號：hx_post="/tasks" 到了標記裡是 hx-post="/tasks"。每一支 macro 的每一個 hx-*、aria-*、data-* 都走這條路徑

用角色，不用顏色

variant、tone、category 指的是角色（success、destructive、muted），不是顏色。顏色歸 token 層，換品牌只動一個地方

按鈕與圖示

最小的兩個元件，加上其他每一支 macro 都會轉手的那段管線。

ui/button.html

button(label, variant="", size="", type="button", href=none, icon_name=none, icon_end=false, disabled=false)

傳了 href 就會渲染成 <a>，外觀與行為仍然是一顆按鈕。

button_group(gap=2, orientation="horizontal")

只負責間距。每顆按鈕保有自己的 variant。

區塊：按鈕

ui/icon.html

icon(name, size=16, cls="")

1,767 個 Lucide 名稱。名稱不存在時會在渲染階段丟例外，而不是畫出一片空白。

ui/attrs.html

attrs(mapping)

app 不會呼叫它。每一支 macro 都以 **kwargs 收尾並交給它處理，hx_post="/tasks" 因此在標記裡變成 hx-post="/tasks"。

版面與頁面結構

這一組全部吃區塊，因為版面 macro 的本質就是包裝。任何 utility class 之前先用它們——這正是封閉詞彙表存在的理由。

ui/layout.html

stack(gap=4, align=none)

垂直節奏。頁面各段落之間的預設間距。

區塊：子元素

row(gap=3, align="center", justify=none, wrap=true)

水平排列，預設會換行，窄螢幕不會被裁掉。

區塊：子元素

grid(cols=3, gap=4)

cols 只有 2、3、4。斷點屬於 macro；呼叫端自己挑斷點，就是版面詞彙表退回 utility class 的起點。

區塊：子元素

split(aside="md", gap=6)

用 {% call(slot) split() %} 呼叫，區塊會被渲染兩次——slot="main" 一次，slot="aside" 一次。

區塊：兩個插槽——main 與 aside

centered(width="sm", gap=6)

這個檔案其他 macro 給不了的寬度上限。width 只有 xs、sm、md、lg、xl、prose——登入卡片、設定表單、純文字頁面。只做水平置中。

區塊：子元素

page_header(title, description=none)

不給區塊時就只有標題與說明。區塊是動作插槽，所以按鈕在任何寬度下都與標題齊平。

區塊：動作按鈕（可省略）

section(title=none, description=none, gap=4)

比 page_header 低一階。頁面上不只一個主題時才需要它。

區塊：子元素

divider()

用 border token 畫的細線，明暗兩套配色都成立。如果這個分界有名字，用 section 標題更好。

ui/sidebar.html

sidebar(id="sidebar", label="Main", side="left", open=true, header=none, footer=none)

外殼的 sidebar 區塊填它，或者 nav 區塊填 nav_links——兩者擇一。

區塊：群組

sidebar_group(title=none)

區塊：sidebar_link() 呼叫

sidebar_link(request, route, label, icon_name=none)

route 是路由名稱，不是網址。作用中狀態由 is_active 決定，連結不可能跟所在頁面對不上。

sidebar_submenu(label, icon_name=none, open=false)

區塊：sidebar_link() 呼叫

sidebar_trigger(target="sidebar", label="Toggle navigation")

有 sidebar 時，外殼已經在標頭放了一顆。

資料呈現

一列資料、一個數字、一份清單長什麼樣子。清單在 Python 裡組好——在模板裡 zip 兩個 list，是模板在做 router 的工作。

ui/data.html

badge(label, variant="")

variant 是角色：success、warning、destructive、info、secondary、outline。

card(title=none, description=none, size="", actions=none, padded=true)

padded=false 讓內容貼到卡片邊緣——表格或程式碼區塊需要的就是這個。

區塊：內容

stat(label, value, hint=none, icon_name=none, tone=none)

單一數字。要放好幾個就用 metric_group。

metric_group(items, cols=3)

items 是 (label, value) 的序對清單。

progress(value, label=none)

value 是 0–100。

empty_state(title, description=none, icon_name="sparkle")

rows 是空的時候 table 會替你渲染它——傳 empty_title 與 empty_description，不要自己寫那個分支。

bullet_list(tone="muted")

區塊：list_item() 呼叫

list_item()

區塊：文字

item_list()

區塊：item() 呼叫

item(title, description=none, icon_name=none, actions=none, href=none, clamp=true)

clamp=false 讓說明超過兩行——定義列表需要，動態列表不需要。

avatar(name, src=none, size="", initials=none, badge_tone=none, badge_icon=none)

沒有另外指定時，縮寫由 name 推導。

avatar_group(overflow=none, label=none)

區塊：avatar() 呼叫

code_block(source, label=none, wrap=false)

它自己帶捲動區與可聚焦性，溢出的程式碼用鍵盤也到得了。

caption(text=none)

自己站著的一行淡色說明。card、section、page_header 都能畫說明文字，但那些都綁在標題底下。

區塊：文字（可省略）

link(label, href)

kbd(keys)

一個按鍵，或一組組合鍵。

ui/table.html

table(columns, rows=none, empty_title="Nothing here", empty_description=none, empty_icon="list", target=none, swap="outerHTML", push_url=true, select_name="selected", select_label="Select all rows")

columns 是 dict 的清單——label，可選 align、width、sort、sort_url 或 select。傳了 rows，空資料的情況就歸 macro 管；傳 rows=none 則永遠自己渲染 body。有 sort_url 的欄位會變成可排序表頭，給了 target 那些連結就同時是 htmx swap。

區塊：資料列

cell(value=none, tone=none, numeric=false, align=none)

文字用 value，標記則省略 value 改用區塊。tone 是封閉查表，顏色傳不進來。

區塊：儲存格內容（可省略）

row_actions()

最後一格，靠右且緊湊。

區塊：按鈕

select_cell(value, name="selected", checked=false, label=none)

{"select": true} 欄位在資料列這一半。就是一個普通的 checkbox 加普通的 name，所以選取結果照 selected=3&selected=7 送出。要給 label——id 不是 label。

select_count(name="selected", label="{n} selected", zero="None selected")

即時顯示選了幾列。兩個字串都寫在標記裡，所以翻譯頁面能翻譯它們。傳 zero=none 則在沒有選取時自己隱藏。

select_scripts()

載入 js/select.js：從表頭的核取方塊勾選整欄、顯示部分選取狀態、把選到的列上色。逐頁載入，不進 shell。

page_size(url, per_page, options=(10, 25, 50, 100), param="per_page", keep=none, target=none, label="Rows per page", apply_label="Apply")

一個 GET form，因為單獨一個 select 沒有辦法對變更做出反應。url 不能帶 query string——原生送出會把它整段丟掉——所以篩選要放在 keep，以 hidden 欄位傳遞，但絕不放頁碼。給了 target，select 自己就會套用，送出鈕只在沒有腳本時才渲染。

pagination(page, pages, url, param="page", total=none, per_page=none, target=none, swap="outerHTML", push_url=true, window=1, label="Pagination")

url 是清單的網址，不帶頁碼參數，頁碼由 macro 接上去。只有一頁或更少時不渲染。total 與 per_page 要一起給，才會出現「76–100 of 210」那一行。

表單

每個欄位都吃 name、label、hint、error、id。傳了 error，欄位會一次畫出訊息、紅框，以及 aria-describedby 的接線。

ui/form.html

form(action=none, method="post", target=none, swap="outerHTML", reset_on_success=false, card=true, encoding="urlencoded")

target 與 swap 是 htmx 那一組。encoding="json" 會送出 JSON，這時頁面需要 form_scripts()。

區塊：欄位

form_scripts()

放在頁面裡，不在外殼——encoding="json" 需要的就是它。

field_row(template="two", gap=3)

一行放兩到三個欄位，窄螢幕收成一欄。

區塊：欄位

fieldset(legend=none, hint=none)

表單裡一個具名的群組，附上該群組需要的 legend。

區塊：欄位

text_field(name, label=none, value="", placeholder="", type="text", required=false, hint=none, error=none, id=none)

textarea_field(name, label=none, value="", placeholder="", rows=none, required=false, hint=none, error=none, id=none)

select_field(name, label=none, options=(), selected=none, id=none, blank=none, hint=none, error=none)

options 是 (value, label) 的序對清單。

checkbox_field(name, label=none, checked=false, value="on", hint=none, error=none, id=none)

switch_field(name, label=none, checked=false, value="on", hint=none, error=none, id=none)

radio_group(name, label=none, options=(), selected=none, hint=none, error=none, id=none)

range_field(name, label=none, value=50, min=0, max=100, step=1, hint=none, error=none, id=none, output=false)

output=true 會在滑軌旁顯示即時數值，數值來自控制項本身，不是另一個來源。

input_group_field(name, label=none, value="", placeholder="", type="text", start=none, end=none, required=false, hint=none, error=none, id=none, revealable=false, reveal_show="Show", reveal_hide="Hide")

start 與 end 是前後綴——貨幣符號、單位，或一顆按鈕。revealable=true 會加上密碼欄位需要的顯示／隱藏切換，這時頁面需要 reveal_scripts()。

reveal_scripts()

放在頁面裡，不在外殼——revealable=true 需要的就是它。監聽器掛在 document 上，所以 422 換進來的面板裡那顆按鈕一樣能用。

導覽

這裡流通的是路由名稱。沒有一支吃網址，所以搬動路由不會留下死連結。

ui/nav.html

brand(label, href="/", icon_name=none, icon_src=none)

Lucide 圖示用 icon_name，自己的識別圖用 icon_src。

nav_links(request, links)

links 是 (route, label) 的序對清單。標頭版的 sidebar 替代方案。

theme_toggle()

外殼已經放了一顆；只有在你換掉 header_actions 時才需要自己呼叫。

breadcrumb(trail, separator="chevron", label="Breadcrumb")

trail 是 (label, href) 的序對清單，href=none 標示目前這一頁——也就是最後一項，它不是連結。

ui/tabs.html

tabs(items, label="Tabs", selected=none, orientation="horizontal")

items 是 {id, label} 的清單。selected 指名一開始就打開的分頁，由伺服器決定，而不是繪製後由腳本決定。

區塊：tab_panel() 呼叫

tab_panel(id, lazy=none, on=none, include=none)

id 必須跟分頁的一致。這組配對就是 Basecoat 鍵盤行為所讀的整份 aria 契約。

區塊：內容

tab_panel("detail", lazy=url_for(request, "detail"), on=["task-selected"], include="[name=task_id]")

lazy 是一個 URL：分頁被選到時，這個面板才去抓自己的內容，區塊裡放的是在那之前的暫代內容。on 列出它顯示中要跟著更新的廣播，include 是它要送出什麼的選擇器。不能用 revealed——被 display:none 藏起來的面板回報的是全為零的矩形，剛好通過 htmx 的可見性判斷，所以 revealed 會在頁面載入時就抓。

區塊：the placeholder 呼叫

浮層與展開

會打開的東西都在這裡。開闔行為是 Basecoat 的，外殼已經載好，所以這些 macro 只負責帶那份 aria 契約。

ui/overlay.html

popover(id, label, variant="outline", size="", side="bottom", align="center", width="lg", icon_name=none)

浮動面板裡放任意標記。若是一串選項，用 dropdown_menu。

區塊：內容

dropdown_menu(id, label, variant="outline", size="", side="bottom", align="start", width="default", icon_name=none)

區塊：menu_item() 呼叫

menu_item(label, shortcut=none, variant="", disabled=false, checked=none, radio=false, href=none)

checked 與 radio 會給這一項對應的 aria 角色。

menu_group(heading=none, id=none)

區塊：menu_item() 呼叫

menu_separator()

select_menu(name, options=(), selected=none, id=none, placeholder="Select…", width="lg", label=none, multiple=false, close_on_select=false, visible_label=none, hint=none, error=none)

外觀受控、但仍然會送出欄位的 select。multiple=true 需要頁面上有 multiselect_scripts()。label 是 aria-label，畫不出東西；visible_label 會讓它變成一個 field，帶上其他欄位都有的外框、標籤與訊息行。

combobox(name, options=(), selected=none, id=none, placeholder="Select…", empty="No results found.", label=none, multiple=false, close_on_select=false, visible_label=none, hint=none, error=none)

加了篩選框的 select_menu。multiple=true 的規則相同，visible_label 也相同。

multiselect_scripts()

放在頁面裡。少了它，multiple=true 會送出一個 JSON 字串，而不是重複的欄位。

drawer(id, title=none, description=none, side="bottom", footer=none, dismissible=true)

區塊：內容

drawer_trigger(label, target, variant="outline", size="", icon_name=none)

command(id, placeholder="Type a command or search…", empty="No results found.", label="Command menu", dialog=false, bordered=true)

dialog=true 讓它變成浮層命令列，而不是內嵌清單。

區塊：command_group() 呼叫

command_group(heading=none, id=none)

區塊：command_item() 呼叫

command_item(label, keywords=none, icon_name=none, shortcut=none, disabled=false, filter=none, href=none)

除了 label 之外，篩選框還會比對 keywords。

ui/disclosure.html

collapsible(summary, open=false, icon_name=none)

一個會展開的段落。底層是 <details>，關掉腳本也能用。

區塊：展開後的內容

accordion(multiple=false, label=none)

multiple=false 時，打開一個就會關掉其他的。

區塊：collapsible() 呼叫

tooltip(text, side="top", align="center")

用 CSS ::after 做的，沒有第二個元素、沒有腳本。文字不在無障礙樹裡——tooltip 是提示，不能當成唯一的標籤，而且裡面不能有標記。

區塊：被它包住的元素

回饋

介面回話的方式。variant 決定顏色，對 alert 來說還決定螢幕閱讀器要不要打斷。

ui/feedback.html

spinner(size="default", tone="muted", label=none, indicator=false)

indicator=true 讓它成為 htmx 的 indicator：對應的請求在途中才會顯示。

alert(title, body=none, variant="", icon_name=none)

variant="destructive" 會拿到 role="alert"，會打斷螢幕閱讀器；其他都是 role="status"，會等到一個停頓。

區塊：動作按鈕（可省略）

skeleton(shape="text", width="full", lines=1, label=none)

shape 有 text、heading、control、avatar、block。

dialog(id, title=none, description=none, size="default", footer=none, dismissible=true)

原生 <dialog>。footer 是插槽而不是區塊，因為區塊已經給了內容。

區塊：內容

toaster(align="end")

每頁一個，放在外殼的 toasts 區塊。伺服器送出的 toast 走 HX-Trigger。

區塊：toast() 呼叫（可省略）

toast(title, description=none, category="info", duration=none, action_label=none, action_href=none)

外殼

是 block，不是 macro：唯一一個用 extends 而不是 import 的檔案。

ui/shell.html 提供 <head>、主題閃爍防護、資源連結， 以及 header／main／footer 骨架。app 在自己的 base.html 裡 extends 它一次， 再填需要的 block。sidebar 與 nav 只填一個：外殼依照填了哪一個 排出不同的標頭，兩個都填會得到兩套導覽。 

{% extends "ui/shell.html" %}

{% block site_title %}Acme{% endblock %}
{% block sidebar %}{# 你的側邊欄 #}{% endblock %}
{% block content %}{# 頁面本體 #}{% endblock %}

ui/shell.html

site_title

產品名稱，接在 <title> 裡的頁面標題之後。

title

這一頁的標題。

lang

<html lang> 的值。

brand

標頭上的識別。通常是一次 brand() 呼叫。

nav

標頭導覽。這個跟 sidebar 只能填一個。

sidebar

側邊欄。這個跟 nav 只能填一個。

header

整條標頭；上面那幾個插槽不夠用時才動它。

header_actions

標頭右端。預設是 theme_toggle()。

sidebar_trigger

窄螢幕上打開側邊欄的按鈕。

content

頁面本體。

footer

頁尾文字。

footer_wrapper

包住頁尾的那個元素。

stylesheets

你自己的樣式表——token 覆寫與元素層級的排版。

head

<head> 裡的其他東西：meta、og:。

toasts

toaster() 的位置。外殼預設會渲染一個。

scripts

你的腳本，放在 <body> 結尾。要用 defer——htmx 與 Basecoat 也是 deferred，這裡放普通腳本會比它們先執行。

Globals

每個模板裡都有，不用 import，也不用從 context 傳。

build_environment()

url_for(request, name, **params)

由路由名稱換到網址。用名稱不用路徑，搬動路由時每個連結都會跟著更新。

is_active(request, name)

這次請求指向該路由時為真。sidebar_link 用它標示作用中狀態。

fjkit_static(path)

掛載後靜態目錄下的網址，帶上 ?v=<mtime>，瀏覽器就不會拿舊的樣式表去配新的標記。

fjkit_version

頁尾那幾個版本號：fjkit、fastapi、jinja2、basecoat、htmx。

fjkit_icon_path(name)

某個 Lucide 名稱的原始 SVG path 資料。模板要呼叫的是 icon()。

htmx 屬性

它們不屬於 fjkit，但會傳給 fjkit macro，所以列在索引旁邊。

這裡每一個都以多出來的關鍵字傳給 macro，再進到標記裡：{{ button("Refresh", hx_get="/tasks/board", hx_target="#board") }}。底線在途中變成連字號，整套整合只有這件事：kit 裡沒有一支 macro 有 htmx 專屬參數，也不需要有。完整參考是 htmx.org/reference，底下列的是 fjkit 頁面實際用到的部分。

送什麼請求

動詞與網址。

hx-get="/tasks" hx-post="/tasks" hx-put="/tasks/5" hx-patch="/tasks/5" hx-delete="/tasks/5"

送出請求。回應是 HTML 不是 JSON——這就是它跟 fetch() 的全部差別。

回應放到哪裡

哪個元素被換掉，以及怎麼換。

hx-target="#board" a CSS selector hx-target="closest tr" the nearest ancestor hx-target="this" the element itself hx-target="next .row" the one after it

沒寫的話，預設就是觸發請求的那個元素。

hx-swap="outerHTML" replace the target hx-swap="innerHTML" replace what is inside it hx-swap="beforeend" append (afterbegin prepends) hx-swap="afterend" insert after (beforebegin: before) hx-swap="delete" remove it (none: change nothing)

修飾詞接在同一個字串上：swap:200ms、settle:100ms、scroll:top。

什麼時候觸發

同一個屬性，每種寫法是一種不同的用途。

hx-trigger="click" hx-trigger="submit" hx-trigger="change"

預設值——按鈕是 click、表單是 submit、輸入欄位是 change。只有要加修飾詞時才需要寫出來。

hx-trigger="keyup changed delay:400ms"

邊打邊查。changed 讓值沒變時不送請求；delay 把連續按鍵防抖。

hx-trigger="revealed"

延遲載入：元素捲進畫面時才觸發。它是用 getBoundingClientRect 判斷的，所以放在 overflow 容器裡、或被 display:none 藏起來的元素都不適用——隱藏元素回報的是全為零的矩形，會被判定為可見。

hx-trigger="intersect once" hx-trigger="intersect threshold:0.5"

改用 IntersectionObserver 做延遲載入，隱藏的元素會被正確判定為未交會。分頁面板或捲動容器裡要用這個。不加 once 的話，每次重新可見都會觸發；root: 與 threshold: 對應 observer 自己的選項。

hx-trigger="load"

元素一被插入就觸發一次。

hx-trigger="every 2s"

輪詢。回傳不帶這個屬性的標記就會停下來。

hx-trigger="click from:body"

監聽別的地方——鍵盤快捷鍵，或選單外的點擊。

還會一起送出的東西

額外資料、確認、瀏覽紀錄。

hx-vals='{"id": 3}'

除了表單欄位以外，一起送出的值。

hx-include="#filters"

要一起送的其他欄位——例如放在表單外的篩選列。

hx-confirm="Delete this task?"

送出請求前先跳一個原生確認視窗。

hx-indicator="#spinner"

請求在途中時，那個元素會拿到 htmx-request class。spinner(indicator=true) 已經是為它準備好的形狀。

hx-push-url="true"

把網址推進網址列，上一頁才會正常運作。

hx-swap-oob="true"

寫在回應裡，不是寫在觸發端：依 id 把頁面上另一個元素也換掉。

路由讀寫的標頭

htmx 的另外一半，住在 Python 裡而不是模板裡。

HX-Request: true (request)

每個 htmx 請求都會帶。同一個路由靠它決定：導覽回整頁，局部更新回 fragment。

HX-Trigger: {"toast": {…}} (response)

觸發一個前端事件。在路由裡發出的 toast 就是這樣送到外殼裡的 toaster。

HX-Redirect: /tasks (response) HX-Refresh: true (response)

由 fragment 回應要求的整頁導覽。

HX-Retarget: #errors (response)

由伺服器改寫 target——錯誤訊息該去的地方，跟成功時不一樣。
