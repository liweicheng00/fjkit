What is missing compared with `showModal()` is *modality*: the page behind stays reachable by Tab and by a screen reader, so this is `role="dialog"` without `aria-modal`. That is the honest label for what the markup does. It is the right trade for showing a record, and the wrong one for a confirmation that must not be dodged — `hx-confirm` still covers that case, and a real modal is a decision about shipping JavaScript (CHARTER.md §11.3), not something to fake with CSS. **The body carries `id="-body"`**, which is the seam htmx needs: the trigger fetches the content and targets that id, so a list of rows renders one shell per row and pays for the contents only when one is opened. {{ button("Details", popovertarget="task-7", hx_get=url_for(request, "task_detail", task_id=7), hx_target="#task-7-body") }} Both halves happen on the one click, in the order that reads best: the panel opens immediately with whatever the shell holds (a spinner), and the response replaces it. htmx does not cancel the click's default action on a plain button — it only does that for anchors and submit buttons — so the popover still opens. A shell per row also means an open panel can never show the previous row's data while a request is in flight. One shared dialog re-targeted at each row is the right shape for a long list; it just has to accept that flash. One trap, and it is silent: `hx-swap` is inherited. A trigger nested inside an element that swaps itself with `outerHTML` — a row that polls, say — replaces the body element rather than its contents, id and all, so the first open works and none of the others do.
