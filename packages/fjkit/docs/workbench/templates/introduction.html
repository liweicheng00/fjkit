A FastAPI service that needs a real interface has two usual answers. Write Jinja and hand-roll the CSS, and you own a design system you did not set out to build. Reach for a front-end framework, and you own a second build, a second language and a second thing to deploy.

fjkit is a third answer. The interface is Jinja macros beside your routes, and the stylesheet was compiled when fjkit was released — so your repository gets no package.json, and there is nothing to rebuild when you edit a template.

Add uv run fjkit check app/templates to CI. It fails when a template uses a class or a colour outside the kit's vocabulary.
