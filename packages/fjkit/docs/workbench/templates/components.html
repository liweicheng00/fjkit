columns is a list of dicts — label, and optionally align, width, sort, sort_url or select — and the macro tests rows to decide whether to render your body or the empty state. It takes rows without iterating them for that reason: the caller writes no if-rows-else branch.

Render each row with a macro call inside your loop. {% raw %}{% include %}{% endraw %} in a loop does a template lookup and builds a new context per row, and is 20–30% slower (jinja-performance.md).

A column carrying a sort_url becomes a sortable header, and pagination goes under the table. Neither builds a URL: the router owns the query string, because it is the only thing that knows which filters are on. Both render real hrefs and take target= to add the htmx swap on top, so sorting and paging work without JavaScript and the URL can be bookmarked.

{% raw %}{"select": true}{% endraw %} puts a batch-selection column in front of the rest. It posts as the repeated field a checkbox column has always sent, and select_scripts() is what ticks the whole column from the header box.

page_size is a <form method="get">, because a bare <select> cannot submit without a script. Its url must carry no query string: a GET submit replaces the whole query with the form's fields, so pass the filters in keep. Do not keep the page number; a new page size invalidates it.
