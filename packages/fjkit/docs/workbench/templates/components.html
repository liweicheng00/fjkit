These four differ in who is waiting and for what, which is also how you pick one. alert is a fact that stays on the page. spinner and skeleton both mean "not yet", and the choice between them is whether you know the shape of what is coming: a skeleton draws that shape, a spinner admits you cannot. dialog interrupts.

Two of them make an accessibility decision for you. alert(variant="destructive") takes role="alert", which interrupts a screen reader mid-sentence; every other variant is role="status", which waits for a pause. And a multi-line skeleton is one live region, not six — six bars are one thing loading.

avatar is the one to read the signature of. The name is both the alt text and the fallback initials, so the two cannot disagree, and the initials leave the accessibility tree the moment an image carries the name — otherwise the same person is announced twice, once properly and once as two stray letters.

breadcrumb takes (label, href) pairs where a null href is the current page. That is deliberate: the usual way this component goes wrong is a trail whose last entry links to the page you are already on, and the shape of the argument makes that unspellable.

collapsible is a native <details>: the open state, the keyboard operation and the disclosure role all come from the element, and Basecoat animates it with CSS. tooltip is drawn entirely from a data-tooltip attribute — no second element exists. tabs is Basecoat's, and the shell already loads it.

The tooltip's mechanism has one consequence worth stating plainly: CSS content() is never in the accessibility tree. A tooltip is a hint, never the only label a control has. Give the control an aria_label when the tooltip is the only text on it.

Everything in ui/overlay.html is driven by Basecoat's own JavaScript, which the shell already loads and which re-scans on htmx:afterSwap — so an overlay that arrives in a swap works with nothing extra.

What they share is id wiring. A trigger and its panel find each other through four related ids, and getting one wrong fails silently: the panel opens but is never announced, or never opens at all. Every macro here takes one id and derives the rest. That is the whole reason they are macros rather than markup to copy.

select_menu and combobox put their value in a hidden input, pre-filled — upstream ships value="" and writes it from JS, which loses the selection on any round trip that re-renders the fragment. Prefer select_field to either: a native <select> is correct for free and costs one element instead of thirty.
