接下來是 fjkit 那一半。partial 就是名字以底線開頭的模板。它不 extends 外殼，自己宣告 import， 並且把自己包在「會被換掉的那個元素」裡。整頁用 {% raw %}{% include %}{% endraw %} 把它放進去；每個 htmx 端點則是光禿禿地回它。

這就是為什麼 fjkit app 裡沒有「更新那一列」這條程式路徑。 每一次異動都重新渲染整塊板子的 partial 再換進去。 「板子長什麼樣」只有一份定義，第一次上色用它，之後每個請求也用它。 真正的檔案在 repo 的 examples/fjkit-demo/app/templates/tasks/。

到這裡為止每一次 swap 都只有一個 target。會變的東西都包在同一個元素底下時，那樣就夠了—— 板子就是一個 <div id="board">，上面每一顆按鈕都指著它，每一次回應都是整塊板子。

搜尋結果不是一個東西。一次查詢要動的是：表格上方那排計數、表格自己、側欄的進度卡、facet 清單 與同負責人面板、表格下面的明細面板——六塊分散在三個地方，唯一同時包住它們的元素叫 <body>。換掉 body 就是重新整理，只是多繞了一圈。

所以回應把另外五塊走頻外（out of band）送回去——不走 hx-target 描述的那條唯一通道。每一塊靠自己身上的 id 說出它要去哪裡。

換來的好處是：哪一塊放在哪裡由頁面決定，而且只決定一次。把 facet 卡從側欄搬到主欄， router、response model、swap 三者一個字都不用改。實際的檔案是 repo 裡的 examples/fjkit-demo/app/templates/search/——而下一課講的是同一頁的另外一半， 因為真實的畫面兩種都需要。

{% endcall %} {% endcall %} {# ============================================================== 07 #} {% set t07 %}第 06 課的反面題：觸發者產生的是一個 id，而每一塊區域拿著這個 id 要問的問題都不一樣。{% endset %} {% call lesson("broadcast", "07", "一個 id，好幾份 fragment：HX-Trigger", t07, tag="htmx") %} {% call prose() %}

上一課成立的前提，是一支 handler 有辦法一次回答所有區域——一次查詢、六份 fragment、 一個裝得下全部的 response model。在同一頁上點開一列不是這個形狀。點擊產生的是一個 id，而在意它的每一塊面板各自需要不同的查詢：那個任務的細節、 那個負責人手上的其他任務。要一支 handler 回答全部，它就得 import 這一頁上的每一個 service， 而且多加第三塊面板就要回頭改它。

所以這次選取回應的是它自己那一塊——結果表，而且那一列現在被標記起來了—— 並把 id 放在 HX-Trigger 裡送出去。htmx 把這個標頭轉成一個 DOM 事件， 在意它的 fragment 各自聽到之後，自己去要自己的資料。這條路由不知道有幾個訂閱者， 也不知道它們存在。多一塊面板就是多一個訂閱者，沒有任何一條路由要改。

事件宣告在 hx_trigger，而它是 @render 的參數、不是 handler 自己寫的標頭， 理由只有一個：這樣它在會渲染的路由上是同一套用法。callable 每次請求解析一次， 依名字從 handler 自己的參數裡取值——這裡是 task_id——外加 result， 也就是 handler 的回傳值。callable 回傳 None 就什麼都不發，所以一條路由可以只在某些時候廣播。

除此之外那條路由沒有任何特別之處。它就是一條普通的 partial 路由——一份樣板、一個 response model——上面掛了一個事件，而這正是這個模式便宜的原因：那次 swap 與那次廣播是一趟來回， 寫在同一個地方。

同一頁上的第二個動作展示了另外一半。推進會改變狀態，所以它發出不同的事件， 而在意的是另一組 fragment。

撐住這整套的只有一條規則：一條路由回應的那份 fragment，不可以訂閱這條路由發出的事件。 它已經被就地換掉了，再聽到那個事件就是同一次點擊抓它第二次——而如果那份 fragment 就是自己的 target，它永遠不會停。htmx 不會攔你，因為「訂閱者去要自己的 URL」正是那些屬性寫的意思。 所以結果表只聽 task-changed、detail 面板只聽 task-selected： 每一份對其中一個事件是 target、對另一個是訂閱者，從不對同一個事件兩者兼具。
