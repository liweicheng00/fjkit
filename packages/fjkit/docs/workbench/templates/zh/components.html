這四個的差別在誰在等、等什麼，挑哪一個也是照這條分。alert 是一件留在頁面上的事實。 spinner 和 skeleton 都表示「還沒好」，選哪一個取決於你知不知道等一下會出現什麼形狀： skeleton 把那個形狀畫出來，spinner 承認你畫不出來。dialog 則是打斷。

其中兩個替你做了無障礙的決定。alert(variant="destructive") 會拿到 role="alert"，那會打斷螢幕閱讀器正在唸的句子；其餘每個 variant 都是 role="status"，會等到一個停頓。而多行的 skeleton 是一個 即時區域而不是六個——六根長條是一件事在載入，不是六件。

avatar 是值得先讀簽名的那一個。名字同時是 alt 文字和退回時的縮寫， 所以兩者不可能互相矛盾；而且一旦有圖片承載了名字，縮寫就會退出無障礙樹——否則同一個人會被唸兩次， 一次是正常的，一次是兩個沒頭沒尾的字母。

collapsible 是原生的 <details>：開合狀態、鍵盤操作、disclosure 角色 全部來自那個元素，Basecoat 用 CSS 替它加動畫。tooltip 完全畫自一個 data-tooltip 屬性——根本不存在第二個元素。tabs 是 Basecoat 的，外殼已經載好了。

tooltip 的機制有一個後果要講白：CSS content() 從來不會進無障礙樹。 tooltip 是提示，永遠不能是一個控制項唯一的標籤。當 tooltip 是那個控制項身上唯一的文字時， 請另外給它 aria_label。

ui/overlay.html 裡的每一個都由 Basecoat 自己的 JavaScript 驅動，外殼已經載了它， 而且它會在 htmx:afterSwap 時重新掃描——所以由 swap 送進來的浮層不需要任何額外處理就能用。

它們共同的東西是 id 接線。一個觸發元素和它的面板靠四個相關的 id 互相找到對方， 錯一個就靜靜地失敗：面板打得開但永遠不會被唸出來，或者根本打不開。這裡每個 macro 都只收一個 id 再自己推導其餘的。這就是它們是 macro 而不是一段可以複製的標記的全部理由。
